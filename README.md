```text
Пользователь 1 --\
Пользователь 2 ----> VPS-1 ----> VPS-2 ----> Интернет
Пользователь 3 --/
```

Для каждого пользователя на VPS-1 следует создавать отдельный клиентский профиль.
На VPS-2 достаточно одного служебного профиля для VPS-1 независимо от количества
пользователей каскада.

Пользователь также может иметь отдельный профиль VPS-2 и выбирать способ подключения:

```text
Напрямую: Пользователь -> VPS-2 -> Интернет
Каскад:   Пользователь -> VPS-1 -> VPS-2 -> Интернет
```

## Возможности

- проверка контейнера `amnezia-awg2` и серверного интерфейса `awg0` на VPS-1;
- автоматическое определение клиентской IPv4-подсети VPS-1;
- создание выходного интерфейса `awg-out`;
- отдельная таблица policy routing для VPN-клиентов;
- NAT клиентской подсети через VPS-2;
- уменьшенный MTU и TCP MSS clamping для стабильной работы двойного туннеля;
- автоматический запуск `awg-out` вместе с контейнером после перезагрузки;
- очистка пустых параметров `I1`-`I5`;
- сохранение заполненных параметров маскировки AWG 2.0;
- резервное копирование изменяемых файлов;
- создание скрипта отката;
- автоматический откат, если настройка завершилась с ошибкой.

## Требования

- VPS-1 и VPS-2 с Ubuntu или Debian;
- права `root` на VPS-1;
- установленный через AmneziaVPN и запущенный AmneziaWG 2.0 на обоих VPS;
- работающий Docker-контейнер `amnezia-awg2` на VPS-1;
- отдельный клиентский профиль, созданный на VPS-2 для подключения VPS-1.

> [!CAUTION]
> Внутренние подсети AWG на VPS-1 и VPS-2 должны различаться. Можно использовать
> любые корректные частные IPv4-подсети. Например, если
> клиенты VPS-1 используют `10.8.1.0/24`, профиль от VPS-2 не должен иметь адрес
> `10.8.1.x`. Используйте на VPS-2 другую сеть, например `10.99.0.0/24`.
> Скрипт проверяет конфликт и остановит настройку до внесения изменений.

Чтобы изменить сеть VPS-2 в AmneziaVPN:

1. Откройте подключение к VPS-2.
2. Нажмите шестерёнку справа от названия сервера.
3. Откройте **Протоколы -> AmneziaWG**.
4. В поле **VPN address subnet** укажите, например, `10.99.0.0`.
5. Сохраните настройки и после этого создайте новый профиль для VPS-1.

Старые профили VPS-2 после смены внутренней сети лучше создать заново.

Скрипт не устанавливает AmneziaWG, Docker и не создаёт клиента на VPS-2.

## Подготовка

1. Установите AmneziaWG 2.0 на VPS-1 и VPS-2.
2. В AmneziaVPN откройте VPS-2 и выберите **Поделиться VPN-доступом**.
3. Создайте отдельный профиль, например `VPS-1-cascade`, выберите оригинальный
   формат AmneziaWG и скопируйте полный конфиг.
4. Подключитесь к VPS-1 по SSH и запустите основной скрипт.
5. Вставьте конфиг VPS-2. Скрипт сам извлечёт из него `Address`.
6. Скрипт покажет готовую команду для VPS-2. Выполните её во втором SSH-окне и
   вернитесь к настройке VPS-1.

> [!IMPORTANT]
> Для каскада нужен клиентский конфиг подключения **VPS-1 к VPS-2**. Не используйте
> серверный конфиг VPS-2 или обычный профиль своего телефона.

## Настройка VPS-1

Подключитесь к VPS-1 по SSH, скопируйте команду целиком и нажмите Enter:

```bash
sudo bash -c 'f=$(mktemp); trap "rm -f \"$f\"" EXIT; curl -fsSL https://raw.githubusercontent.com/ryderams/amneziawg-cascade/main/awg-cascade.sh -o "$f" && bash "$f"'
```

Больше ничего скачивать или загружать вручную не нужно. Скрипт сам загрузится,
запустится и удалит временный файл после завершения.

После вставки конфига скрипт покажет готовую команду для VPS-2 уже с правильным
адресом служебного peer. Ничего подставлять вручную не потребуется. Команда добавит
обратный маршрут на VPS-2 и сохранит его после перезапуска контейнера.

Если команда сообщает, что `curl` не найден, используйте вариант с `wget`:

```bash
sudo bash -c 'f=$(mktemp); trap "rm -f \"$f\"" EXIT; wget -qO "$f" https://raw.githubusercontent.com/ryderams/amneziawg-cascade/main/awg-cascade.sh && bash "$f"'
```

> [!NOTE]
> Команда запускает интерактивный скрипт через временный файл. Благодаря этому
> пользователь сможет вставить клиентский AWG-конфиг прямо в терминал.

На VPS-1 скрипт проверит:

- запущен ли Docker-контейнер `amnezia-awg2`;
- существует ли внутри него серверный конфиг `/opt/amnezia/awg/awg0.conf`;
- запущен ли серверный интерфейс `awg0`;
- доступны ли внутри контейнера `awg`, `awg-quick`, `ip` и `iptables`;
- доступны ли необходимые команды на VPS-1.

Имя контейнера `amnezia-awg2` используется именно для AmneziaWG 2.0. Старый
контейнер AmneziaWG Legacy этим скриптом не поддерживается.
Вставленный профиль VPS-2 также проверяется на наличие параметров `S3` и `S4`,
характерных для AmneziaWG 2.0.

Если начальная проверка не пройдена, настройки системы не изменяются.

## Ввод конфига VPS-2

После проверки скрипт попросит вставить полный клиентский конфиг, созданный на
VPS-2 для VPS-1. Пример с вымышленными ключами:

```ini
[Interface]
Address = 10.99.0.2/32
DNS = 1.1.1.1, 1.0.0.1
PrivateKey = ЗАКРЫТЫЙ_КЛЮЧ_КЛИЕНТА
Jc = 4
Jmin = 10
Jmax = 50
S1 = 21
S2 = 39
S3 = 13
S4 = 16
H1 = 348897818-1231658881
H2 = 2092193350-2147259185
H3 = 2147400654-2147458439
H4 = 2147459541-2147472159
I1 =
I2 =
I3 =
I4 =
I5 =

[Peer]
PublicKey = ОТКРЫТЫЙ_КЛЮЧ_VPS_2
PresharedKey = ПРЕДВАРИТЕЛЬНЫЙ_КЛЮЧ
AllowedIPs = 0.0.0.0/0, ::/0
Endpoint = IP_VPS_2:ПОРТ
PersistentKeepalive = 25
```

После вставки полного конфига нажмите Enter ещё раз, чтобы оставить пустую строку.
Скрипт поймёт, что ввод завершён. Обычная пустая строка между `[Interface]` и
`[Peer]` не мешает: завершение возможно только после заполненной секции `[Peer]`.

Конфиг можно вставлять без ручного редактирования. Скрипт автоматически:

- удалит пустые `I1`-`I5`;
- сохранит заполненные `I1`-`I5`;
- удалит `DNS`, чтобы служебный туннель не менял DNS VPS-1;
- установит `AllowedIPs = 0.0.0.0/0`, поскольку каскад сейчас работает только с IPv4;
- установит `MTU = 1280` и правила TCP MSS clamping для двойной инкапсуляции;
- добавит служебные параметры маршрутизации в секцию `[Interface]`.

## Результат

Внутри контейнера `amnezia-awg2` скрипт создаёт:

```text
/opt/amnezia/awg/awg-out.conf
```

На VPS-1 создаются:

```text
/root/awg-cascade-rollback.sh
/root/awg-cascade-backup-ГГГГММДД-ЧЧММСС
```

Скрипт также добавляет запуск `awg-out` в `/opt/amnezia/start.sh` внутри контейнера.

Все клиенты VPS-1 будут направлены через VPS-2. Их существующие профили менять не
нужно. Для нового пользователя достаточно создать новый клиентский профиль на VPS-1.

В конце скрипт проверяет, что policy routing направляет клиентский трафик в
`awg-out`, установлены правила пересылки и MSS clamping, MTU равен `1280`, а также
подтверждает handshake с VPS-2 и пытается определить внешний IPv4-адрес каскада.

## Проверка

Состояние служебного интерфейса:

```bash
sudo docker exec amnezia-awg2 awg show awg-out
sudo docker exec amnezia-awg2 ip rule
sudo docker exec amnezia-awg2 ip route show table 200
```

Проверка контейнера:

```bash
sudo docker ps --filter name=amnezia-awg2
```

Проверка туннеля и маршрутов на VPS-1:

```bash
sudo docker exec amnezia-awg2 awg show awg-out
sudo docker exec amnezia-awg2 ip rule show
sudo docker exec amnezia-awg2 ip route show table 200
sudo docker exec amnezia-awg2 iptables -nvL FORWARD
sudo docker exec amnezia-awg2 iptables -t nat -nvL POSTROUTING
```

Проверка peer и обратного маршрута на VPS-2:

```bash
sudo docker exec amnezia-awg2 awg show awg0
sudo docker exec amnezia-awg2 ip route show
sudo docker exec amnezia-awg2 iptables -t nat -nvL POSTROUTING
```

## Откат

Для удаления каскада и восстановления сохранённых файлов выполните на VPS-1:

```bash
sudo bash /root/awg-cascade-rollback.sh
```

Резервные копии сохраняются в каталоге вида:

```text
/root/awg-cascade-backup-ГГГГММДД-ЧЧММСС
```

Во время отката контейнер `amnezia-awg2` перезапускается, поэтому активные
подключения к VPS-1 кратковременно разорвутся.

## Безопасность

> [!WARNING]
> Не публикуйте реальные значения `PrivateKey` и `PresharedKey`. Если конфиг с
> ключами попал в открытый доступ, удалите этого клиента на VPS-2 и создайте нового.

Каждому устройству, которое подключается напрямую к VPS-1 или VPS-2, выдавайте
отдельный клиентский профиль. Один служебный профиль VPS-1 -> VPS-2 может передавать
трафик всех пользователей каскада.

## Ограничения

- настраивается только каскад IPv4-клиентов;
- весь трафик клиентской подсети VPS-1 направляется через VPS-2;
- выбор отдельных клиентов для каскада пока не поддерживается;
- поддерживается стандартный контейнер AmneziaWG 2.0 с именем `amnezia-awg2`;
- переустановка или пересоздание контейнера приложением AmneziaVPN может удалить
  каскад; в этом случае скрипт нужно запустить повторно.
